<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo path / branch name → `git` process | Untrusted CLI args and repo state cross into a spawned subprocess |
| git stdout (diff content, commit messages) → go-gitdiff → engine | Untrusted repo content (attacker-influenced added lines) is parsed and regex-scanned |
| matched secret → Finding → output | Raw secret must never escape the redact-at-boundary in `finding.New` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | command.go git spawn | mitigate | Use `exec.CommandContext(ctx, "git", args...)` with an explicit arg slice and `-C <repoRoot>`; never `sh -c` or string interpolation (Security V12). |
| T-03-02 | Denial of Service | parse.go regex over diff lines | mitigate | RE2 (`internal/detect` already RE2-only per CLAUDE.md "What NOT to Use"); linear-time, ReDoS-safe on adversarial diff content. |
| T-03-03 | Information Disclosure | parse.go / output for history findings | mitigate | All findings built via `engine.ScanLine`→`finding.New` (redacts); NEVER log `l.Line` verbatim; reflect-guard `TestNoRawSecretInAnyField` covers new commit fields. |
| T-03-04 | Denial of Service | streaming git process, early cancel | mitigate | `exec.CommandContext` + drain channel + deferred `cmd.Wait()` so context-cancel kills git and no goroutine/process leaks (Pitfall 2). |
| T-03-05 | Spoofing | commit metadata (author/SHA) in fingerprint | mitigate | D-09: commit SHA is metadata only and MUST NOT enter `computeFingerprint`; fingerprint test asserts CommitSHA-set Finding hashes identically. |
| T-03-SC | Tampering | go get github.com/gitleaks/go-gitdiff | mitigate | go-gitdiff is Approved in 03-RESEARCH §Package Legitimacy Audit (gitleaks-maintained fork, in module cache); `go mod verify` after `go get` confirms checksum integrity. |
</threat_model>
