<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo path → `git rev-parse` / `git config` process | Untrusted repo path crosses into a spawned subprocess |
| `mimir hook install` → `.git/hooks/pre-commit` file | Mimir writes OS-registered executable state into the repo |
| installed hook → `mimir scan --staged` subprocess | Hook executes the scanner at commit time; must stay offline |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-10 | Tampering | hook-dir resolution / config reads | mitigate | `exec.Command("git", args...)` explicit arg slice for `rev-parse`/`config`; never `sh -c` with interpolated repo paths (Security V12). |
| T-03-11 | Tampering | install overwriting a user's existing pre-commit hook | mitigate | Refuse to write when a non-marker `pre-commit` exists unless `--force` (D-05); uninstall deletes only the marker-bearing managed hook (Runtime State Inventory). |
| T-03-12 | Tampering | resolved hook path escaping the repo | mitigate | Validate the `rev-parse --git-path hooks` result is under the repo before writing; create dir + set exec bit 0755 only there (Security V12). |
| T-03-13 | Information Disclosure | hook output at commit time | mitigate | Hook runs `mimir scan --staged` whose findings are redacted at `finding.New`; no raw secret in hook stderr/stdout (asserted in TestHookBlocksCommit). |
| T-03-14 | (policy) Info Disclosure | network call from hook (verification) | mitigate | Hook invokes `--staged` only, NEVER `--verify` (VERIFY-01); `TestHookOffline` asserts no `--verify` in the hook body (offline guarantee, criterion 4). |
</threat_model>
