<objective>
Deliver the baseline vertical slice (SUP-03) plus the cross-cutting transparency
wiring: a developer runs `mimir scan --baseline-out .mimir-baseline.json` to snapshot
known findings (raw-secret-free by construction, criterion 3), then
`mimir scan --baseline .mimir-baseline.json` so only NEW findings alert — and a

`--show-suppressed` audit renderer D-12, path-excluded-counted D-13) and the critical
exit-code fix so suppressed findings never flip CI to failure (IFACE-02, Pitfall 5).

DEFINED by Plan 02 (which also owns the inline-ignore scanner annotate-vs-drop branch
so inline-ignored findings can reach this stage). THIS plan reads that same flag value
and owns (a) the baseline reason annotation, and (b) the SHARED `--show-suppressed`
output renderer that re-includes ALL suppressed reasons — `baseline` (this plan),
`inline-ignore` (kept+annotated by Plan 02's scanner), and `allowlist` — each tagged
with its reason in human + JSON. Plan 04 does NOT redefine the flag.

reportable-set choice — proceed. RESEARCH.md `## Open Questions` is marked RESOLVED.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Finding set → baseline file (write) | Redacted findings serialized to disk; must never contain a raw secret |
| baseline file (read) → matcher | Untrusted/attacker-crafted baseline JSON parsed into membership sets |
| --baseline path arg → os.ReadFile | User-controlled file path |
| suppressed findings → exit code | Exit code must reflect only NEW (non-suppressed) findings |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-10 | Information Disclosure | raw secret leaks into the committed baseline (criterion 3) — HIGH | mitigate | WriteBaseline serializes only the redacted `Finding` (D-09; Finding never stores the raw value — finding.go:3-6); `TestBaselineNoRawSecret` + `TestBaselineOutNoRawSecret` self-scan assert no raw fixture-secret substring appears (mirrors OUT-03) |
| T-02-11 | Tampering | malformed/attacker-crafted baseline JSON crashes or silently drops findings | mitigate | `json.Unmarshal` into a typed envelope; decode error → descriptive wrapped error → exit 2 (fail loud, no panic, Security V5); OR-match only suppresses exact key matches — a corrupt entry cannot widen suppression beyond its own key |
| T-02-12 | Repudiation | suppressed finding silently flips CI green when it should not — HIGH | mitigate | Exit code counts only `len(newFindings)` (Pitfall 5 fix); D-11 always-shown counts make hidden findings auditable; the shared `--show-suppressed` renderer gives the full per-finding audit trail with reasons for ALL three reasons (D-12) |
| T-02-13 | Information Disclosure | path traversal via --baseline path argument | accept | `os.ReadFile` on a user-supplied path the user already controls; Mimir only READS; no traversal amplification (Security Domain) |
| T-02-14 | Information Disclosure | new omitempty JSON fields break OUT-02 consumers | mitigate | `suppressed`/`suppression_reason` are `omitempty`; ScanSummary additions are additive; default (no --show-suppressed) JSON is byte-schema-identical to Phase 1 (TestShowSuppressed asserts absence) |
</threat_model>
