<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| config/mimir.toml regex patterns → regexp.Compile | Embedded ruleset patterns are trusted (developer-authored); user custom rules (Plan 02) are untrusted and validated separately |
| File line content → ScanLine | Attacker-controlled repository content enters the regex/entropy pipeline |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-02-01 | Denial of Service | `internal/detect/engine.go` — all 15-25 rules, Aho-Corasick + RE2 | mitigate | All patterns are RE2 (linear-time). Aho-Corasick gate prevents regex execution on unmatched lines. max-file-size cap (10 MB) bounds per-file work. |
| T-02-02 | Information Disclosure | Connection-string `secret_group=3` extraction | mitigate | Password extracted via capture group; passed immediately to finding.New() which redacts at boundary. The raw password group string is never stored or logged. |
| T-02-03 | Information Disclosure | Generic entropy regex — broad match before entropy gate | mitigate | Even if entropy gate passes, finding.New() is the only consumer of rawSecret; redaction is enforced at the constructor boundary. |
| T-02-04 | Tampering | TOML multiline literal strings with complex regex | mitigate | All patterns explicitly RE2-validated by config.LoadDefault() via regexp.Compile. Invalid pattern → LoadDefault returns error → os.Exit(2) in cmd/scan.go. |
| T-02-05 | Denial of Service | generic-api-key regex is broad (many keywords) | accept | Entropy gate (3.5) and allowlist (pure-alpha filter) provide defense-in-depth against false triggers. Keyword pre-filter still applies — line must contain one of the 10 generic keywords. |
| T-02-SC | Tampering | npm/pip/cargo installs | mitigate | No new dependencies in Plan 02 — uses same locked set from Plan 01-01. go mod verify confirms checksums. |
</threat_model>
