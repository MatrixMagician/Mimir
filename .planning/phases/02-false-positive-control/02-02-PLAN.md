<objective>
Deliver the inline-ignore vertical slice (SUP-01): a developer can paste
`// mimir:ignore` (or `mimir:ignore:<rule-id>`) on the secret's line and that
finding disappears from `mimir scan` — end to end, scanner → output → exit code.
Under `--verbose`, every reported finding shows the exact paste-ready directive
plus its fingerprint (criterion 1), so the user knows precisely what to add.

Purpose: This is the first and lowest-risk suppression layer and the most common
day-to-day false-positive escape hatch. It exercises the full pipeline (per-line
detection → drop/annotate → output → unchanged exit code), proving the slice works
before the heavier path-prune and baseline layers land.
Output: internal/suppress/inline.go (+ test), inline wiring in scanFile, the
--verbose hint in human output, the --verbose hint flag/wiring + CLI tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo file line text → directive parser | Untrusted line content drives InlineSuppresses; a malformed/partial directive must fail safe (not suppress unrelated rules) |
| concurrent walk → shared Stats counters | Inline-ignored count is incremented from per-file goroutines |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-03 | Tampering (trust erosion) | over-broad inline suppression | mitigate | Parse the optional `:rule-id` scope (Pattern 1); scoped form suppresses ONLY the named rule (Pitfall 3 test); inline-ignored findings are counted in the D-11 summary so suppression is never silent |
| T-02-04 | Repudiation | inline-ignored finding flips CI green when it should not | accept | Inline ignore is an explicit, same-line, developer-authored opt-out (D-01); the count is always shown (D-11) and --verbose shows the exact directive. Exit code excludes only the explicitly-ignored finding |
| T-02-05 | Denial of Service | data race on the inline-ignored counter | mitigate | Increment via the existing mutex/atomic pattern; verified by `go test -race` |
</threat_model>
