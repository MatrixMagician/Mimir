<objective>
Wire `--verify` end-to-end: register the off-by-default flag, capture the raw map from each scan
source (Plan 01), invoke `verify.Run` (Plan 02) on the post-suppression `newFindings` set before
output, and render the result — a colored ACTIVE/INACTIVE/UNKNOWN tag per verified finding plus a
one-line `Verified: N active, M inactive, K unknown` tally in human output, and the nested
`verification` object in JSON (omitted when absent). `--verify` is strictly label-only: it never
changes the exit-code contract. The pre-existing `TestHookOffline` (hook_test.go:275, added in
Phase 3) already guarantees the hook stays offline; this plan re-confirms it passes (it does NOT
re-create it — a redeclaration would be a compile error).

Purpose: Deliver the user-facing VERIFY-01 capability (opt-in, never in the hook, no network without
the flag) and the VERIFY-02/03 status rendering, completing the phase goal: turning "is this real?"
into an actionable active/inactive/unknown label without touching the detection engine or exit codes.
Output: `--verify` flag + runScan invocation; human/JSON rendering; off-by-default no-network test;
OUT-02 omit-default test; full -race phase gate confirming the existing hook-offline guard holds.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI flag → network capability | --verify is the ONLY switch that turns on outbound calls; default-off is the safety property |
| pre-commit hook → network | The installed hook must NEVER gain a network call (offline guarantee) |
| verification status → output | Status enums cross into human/JSON rendering; must not leak any verifier free-string |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-hook | Tampering (scope creep) | pre-commit hook | mitigate | --verify defaults false; hook template never emits it. Tests: the pre-existing TestHookOffline (hook_test.go:275) + the in-line assertion in TestHookInstall (hook_test.go:62). (BLOCK-WORTHY: hook going online) |
| T-04-default | Information Disclosure / DoS | default scan path | mitigate | No --verify → verify.Run never called → zero network. Test: TestScanNoVerifyNoNetwork. |
| T-04-schema | Tampering | OUT-02 JSON | mitigate | nil Verification → omitempty omits the key → byte-identical non-verify JSON. Test: TestVerifyOmittedByDefault. |
| T-04-exit | Tampering | exit-code contract | mitigate | --verify is label-only; the exit block is unchanged; new findings still exit 1, errors exit 2. Asserted in TestScanNoVerifyNoNetwork. |
| T-04-tty | Information Disclosure | human output | mitigate | The verification tag is a fixed enum (no verifier free-string printed); all other repo-sourced strings keep their sanitizeForTTY pass. |
</threat_model>
